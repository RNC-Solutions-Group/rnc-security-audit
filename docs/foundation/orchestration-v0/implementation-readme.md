# Implementation proofs

This is the home for concise, numbered **capability proof briefs**: design theory, implementation objectives, acceptance criteria, and verified outcomes. Each proof lives as one Markdown file here; no proof-specific subdirectories.

| Proof | Scope | Brief |
| --- | --- | --- |
| **Proof 1** | One complete Gitleaks source scan through one backend, with validated raw and sanitized evidence | [proof-1.md](proof-1.md) |
| **Proof 2** | A second scanner, independent readiness, and partial coverage | Planned |
| **Proof 3** | A second execution backend | Planned |
| **Proof 4** | TUI over the same engine | Planned |
| **Proof 5** | OS-specific portable distribution and verified on-demand tools | Planned |

These are **capability checkpoints, not timeboxed sprints**. Add a `proof-2.md`, `proof-3.md`, etc. only when that checkpoint is scoped. Keep ongoing product intent in the [root README](../../README.md) and operator/architecture illustrations under [design](../design/README.md).

No scanner implementation or accepted proof outcome is implied by this index.
